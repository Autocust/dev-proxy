# Dev Proxy

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

A local, shared HTTP reverse proxy for **Docker Compose (non-Swarm)** projects. Each developer runs a single Traefik instance; all application repositories can be reached at the same time without fighting over port 80.

**Platforms:** macOS and Windows with Docker Desktop + WSL2. **Protocol:** HTTP only, no certificates and no HTTPS configuration. Not intended for production.

## Architecture

```text
macOS / Windows browser
       |
       | http://app.project-a.localhost
       | http://app.project-b.localhost
       v
127.0.0.1:80  ->  Traefik (this repository)
                        |
                 dev-proxy Docker network
                    /           \
          Stack A Nginx    Stack B Nginx
          internal :80     internal :80
```

Traefik discovers services through **Docker labels**. Each project keeps its own `default` network; only the entrypoint service (e.g. Nginx) joins the shared network.

## Requirements

- A working Docker Desktop or Docker Engine, with `docker compose` (Compose v2).
- TCP port **80** on the machine free.
- On Windows: Docker Desktop with the WSL2 backend and integration enabled in the Linux distro you work in. Use the **same Docker Engine** for the proxy and the application stacks.

## Startup (Mac / WSL2)

Clone this repository and, from its directory, run:

```bash
docker compose up -d
docker compose ps
sh scripts/check.sh
```

The `dev-proxy` network is created automatically on first startup and remains usable by application stacks while the proxy is running.

> Do not start a second Traefik for each application repository: the local proxy is **one per machine**, not one per stack.

## Quick test

In a second shell:

```bash
docker compose -f examples/compose.yaml up -d
curl -i -H 'Host: demo.docker.localhost' http://127.0.0.1/
```

If it works, you will get an HTTP response from the `whoami` container, with information about the request. Also try `http://demo.docker.localhost` in the browser.

In Windows PowerShell you can use:

```powershell
curl.exe -i -H "Host: demo.docker.localhost" http://127.0.0.1/
```

**Why test with `Host`?** It verifies routing even if the browser or the local resolver does not yet resolve `.localhost` subdomains.

To shut down the demo:

```bash
docker compose -f examples/compose.yaml down
```

## Connecting an existing project

In the **application project's** `compose.yaml`:

1. Remove the `80:80` port publishing (`ports`) from the Nginx service. Nginx keeps listening on the container's **internal port 80**.
2. Connect **Nginx** to both its project's network (`default`) and `dev-proxy`.
3. Add Traefik labels to the Nginx service. Choose router and service names that are unique across the whole machine.
4. Declare `dev-proxy` as an `external: true` network.

Reference snippet in [`examples/project-nginx.compose.example.yaml`](examples/project-nginx.compose.example.yaml): **it is not a standalone Compose file**, it must be merged into the real Compose file, keeping the existing images, volumes, services and dependencies.

Minimal label example for the Nginx service:

```yaml
labels:
  - traefik.enable=true
  - traefik.docker.network=dev-proxy
  - traefik.http.routers.project-a.rule=Host(`app.project-a.localhost`)
  - traefik.http.routers.project-a.entrypoints=web
  - traefik.http.routers.project-a.service=project-a
  - traefik.http.services.project-a.loadbalancer.server.port=80
```

With two stacks:

- `http://app.project-a.localhost` -> Project A's Nginx
- `http://app.project-b.localhost` -> Project B's Nginx

`Host(...)` rules route the traffic. **Traefik forwards the original Host header**: if Nginx uses `server_name`, update it to match the hostnames, or add the new name to the appropriate virtual host.

### Multiple virtual hosts on the same Nginx

You can create multiple routers pointing to the **same Traefik service** by using labels with distinct names, or a single rule with OR:

```yaml
- traefik.http.routers.project-a.rule=Host(`app.project-a.localhost`) || Host(`api.project-a.localhost`)
```

Make sure Nginx has both `server_name` entries configured if it needs to distinguish them.

## `.localhost` domain resolution

Modern browsers normally treat `.localhost` and its subdomains as local addresses, but not all CLI tools or system resolvers guarantee the same behavior. **Do not rely on a universal wildcard.**

If a hostname does not resolve, add an explicit entry to the hosts file of the machine **the browser runs on**:

```text
127.0.0.1 app.project-a.localhost
127.0.0.1 api.project-a.localhost
127.0.0.1 app.project-b.localhost
```

- **macOS:** `/etc/hosts` (edit with administrative privileges).
- **Windows (Windows browser):** `C:\Windows\System32\drivers\etc\hosts` (editor launched as administrator).
- **WSL2:** `/etc/hosts` inside the distro, if the request comes from Linux tools; it can be regenerated by WSL in some configurations.

Do not use `.local` for new names: on macOS it can interfere with Bonjour/mDNS.

## Everyday commands

```bash
# Start the proxy (from the root of this repository)
docker compose up -d

# Status and logs
docker compose ps
docker compose logs -f traefik

# Stop without removing the network
docker compose stop

# Restart
docker compose start
```

In the application repositories the team keeps using the usual `docker compose up -d` and `docker compose down`.

**Warning:** `docker compose down` run *here* can remove the `dev-proxy` network only when it is no longer used by other containers; if the network is still in use, Docker may report an error and leave it intact. For everyday use prefer `stop` / `start`.

## Troubleshooting

| Symptom | Check / solution |
| --- | --- |
| `port is already allocated` on 80 | An old Nginx, Apache, IIS or another proxy already publishes port 80. Free the port. |
| `404 page not found` from Traefik | The router does not match the `Host` header, or the labels were not applied. Check the hostname and `docker compose logs traefik`. |
| `502 Bad Gateway` / `504` | Verify that Nginx is running, actually listening on the configured internal port, and connected to `dev-proxy`. |
| Browser does not open `*.localhost` | First try `curl -H 'Host: ...' http://127.0.0.1`; then add an explicit hosts entry. Also check any browser proxy/VPN. |
| Nginx serves the wrong site | Fix Nginx's `server_name` entries: it receives the original `Host`. |
| WSL2 works, Windows browser does not | Check Docker Desktop's port publishing, the Docker context, the **Windows** hosts file and possible proxies/firewalls. |

Check the network and the service:

```bash
docker network inspect dev-proxy
docker compose ps
docker compose logs --tail=100 traefik
```

## Security and limitations

- **Local development only:** `127.0.0.1:80:80` limits publishing to the local host; do not expose the proxy to the LAN without weighing the implications.
- **No HTTPS:** do not use this configuration for services that require `Secure` cookies, OAuth logins with mandatory HTTPS redirects, or scenarios that require TLS.
- **Docker socket:** the `:ro` mount prevents modifications to the socket file from the container; it does **not** make the Docker API risk-free. Anyone who can access the Docker API can obtain very high privileges; use only on trusted workstations. A Docker socket proxy with limited permissions is a possible future improvement.
- **Discovery:** `exposedbydefault=false` requires `traefik.enable=true`; do not treat it as a security boundary between containers on the same Docker Engine.
- No Docker Swarm configuration, no administrative dashboard exposed, no public services.
